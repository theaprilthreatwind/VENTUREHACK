# Lean SRS — «ЕНТdigit»

**Версия:** 0.1 (черновик) · **Дата:** 23.09.2026
**Основа:** анализ кода `backend/` и `frontend/` (commit `16f296e` + незакоммиченные правки)

> Lean-подход: фиксируем только то, что влияет на MVP; всё остальное — бэклог с приоритетом.
> **Легенда:** `[ГОТОВО]` — работает в коде · `[В ПРОЦЕССЕ]` — написано частично · `[НЕ НАЧАТО]` — нужно для MVP · `P1/P2` — бэклог после MVP.

**Допущение по MVP (уточняется вопросами в конце):** базовая версия — замкнутый цикл «регистрация/вход → выбор тем → прохождение сессии с проверкой ответов → результат → прогресс в дашборде». Банк вопросов, AI-план и расширенная аналитика — после MVP.

## 1. Архитектурный каркас

### 1.1 Стек

| Слой | Технологии | Комментарий |
|---|---|---|
| Frontend | Next.js 16.3.5 (App Router), React 19.2.8, Tailwind CSS 4, lucide-react, JS + JSDoc | Feature-Sliced Design (`app → views → widgets → features → entities → shared`), алиас `@/*`; нет TypeScript, стейт-менеджера и кеша запросов |
| Backend | Java 25 (pom; README — 21+), Spring Boot 4.1.1: Web MVC, Data JPA, Validation, Actuator; Lombok | Springdoc OpenAPI 3.1 (Swagger UI) |
| БД | PostgreSQL (`ent`, localhost:5432), Hibernate `ddl-auto=update` | Миграций нет |
| Данные на фронте | `apiService` (real) / `mockApiService` + fixtures, флаг `NEXT_PUBLIC_USE_MOCKS` | Переключение npm-скриптами `dev` / `mock dev` |
| AI | Spring AI → Google GenAI starter | Зависимость есть, автоконфиг отключён, кода нет |
| Качество | ESLint (фронт); 1 smoke-тест (бэк, `contextLoads`) | CI/CD, Docker, линтер бэка отсутствуют |

### 1.2 Основные сущности БД (9)

| Сущность | Ключевые поля | Связи | Статус |
|---|---|---|---|
| `User` | email, password, username, token | 1→N TestAttempt | Пароль хранится открытым текстом |
| `Subject` | title, category (COMPULSORY/PROFILE) | — | Нет обратной связи 1→N Topic |
| `Topic` | title | N→1 Subject, 1→N Question | — |
| `Question` | title, type (SINGLE_CHOICE/MULTICHOICE), difficulty | N→1 Topic, 1→N Option | Мультивыбор не поддержан логикой |
| `Option` | text, isCorrect, explanation, photoUrl | N→1 Question | — |
| `TestAttempt` | status (NEW/IN_PROGRESS/DONE), startedAt, finishedAt, duration | N→1 User | `duration` не заполняется |
| `UserAnswer` | isCorrect | N→1 Attempt/Question/Option | Один option на ответ |
| `UserTopicStats` | totalSolved, correctAnswers, successRate, scoreGoal | N→1 User/Topic, unique(user,topic) | Пишется при finish; чтения нет |
| `MarkedQuestion` | — | N→1 User/Topic/Question | Не используется |

**Пробелы модели:** нет таблицы состава сессии (attempt ↔ questions), нет ролей, нет сущностей плана/достижений.

### 1.3 Интеграции

- **REST-API (10 эндпоинтов, 4 контроллера):** `/api/users/*` (регистрация, вход, токен, профиль, список), `/api/subjects/overview`, `/api/practice-page/*` (start/answers/finish), `/api/dashboard/.../target-score`.
- **Frontend ↔ Backend:** JSON по `NEXT_PUBLIC_API_URL` (default `http://localhost:8080`); CORS не настроен.
- **Swagger UI** — автодокументация (springdoc).
- **Планируется:** Google Gemini через Spring AI.

## 4. Уточняющие вопросы (5)

1. **Границы MVP.** Минимум — это замкнутый цикл «регистрация → выбор тем → прохождение → результат + базовый прогресс», а «Банк вопросов», «Аналитика» и «План (AI)» уходят после MVP? Если да, какие из них обязательны в первой версии?
   _Допущение по умолчанию: практика + auth + дашборд; остальное после MVP._
2. **Формат сессии.** Нужен ли режим полноценного ЕНТ (фиксированный набор предметов, таймер, общее количество вопросов, официальная шкала баллов), или сессии всегда «по выбранным темам, сколько хочет пользователь»? Это определит необходимость таймера, шкалы баллов и структуры пробных экзаменов.
3. **Контент и админка.** Откуда берутся вопросы: готовые SQL-скрипты, импорт из файла или нужна админка/редактор? Нужны ли в MVP вопросы с несколькими правильными ответами (тип `MULTICHOICE` уже в enum)?
4. **Что именно должен делать AI-план.** Генерация расписания подготовки, подбор слабых тем по статистике, объяснение решений — какой сценарий главный и когда он нужен (MVP или после)?
5. **Роли и монетизация.** Нужны ли роли (ученик/учитель/админ) и платный доступ (подписка/лимиты бесплатной версии)? От этого зависит модель `User`, авторизация и почти весь UI.
